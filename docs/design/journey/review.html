MR Studio 0.22 · editor review · 24 Nov 2026

The editor, walked as an author

I walked a new author and a returning author through the editor running on the sample table at 1440 × 900, and judged the ribbon and the overall UI by user flow, which is your first rule. The building blocks are good. What they lack is one spine: the setup guide and the ribbon describe the same journey in two different orders, under two sets of names.

Decided: back to the PowerPoint layout

Sanjay, 24 Nov: pages are too big a change; keep the Office/PowerPoint layout people know, which is where the editor started. The noise came from drifting away from it: setup steps became tabs that take over the panel and the canvas. The PowerPoint rules, applied:

  1. The canvas and the left list never change, whatever tab is open. The list is our slide thumbnails: At rest, layers, Controller, Phones.
  2. Tabs hold commands only: Home (selection and arrange), Insert (layer gallery, custom layer, data, media), Design (controller themes, buttons, base map, palette), Present (check, rehearse, present, set up, share), View (Map / Controller / Both, media library, windows), Help.
  3. The right panel is the Format pane: whatever is selected, and the one place to edit it. At rest is a row in the list, like the Slide Master.
  4. Whole-table settings are dialogs, as Slide Size and Set Up Slide Show are: "Table size and place…", "Welcome and languages…", "Screens and calibration…".
  5. The guide is the new-table flow only, like PowerPoint's start screen.

Considered and rejected: pages, not tabs

Sanjay's rule: two views of the app should never do the same thing. Today a tab only swaps the ribbon and the right panel. The middle (map plus controller) and the left list stay the same, so most of the screen is unrelated to the tab, and each tab adds its own form for things another tab already edits. The model that fixes this is DaVinci Resolve's pages, set in journey order. Three rules:

  1. One page, one job, one surface. A page owns the whole window: its tools, its left list, its canvas and its inspector. Place shows the place, Map shows the table, Controller shows the controller. No page shows a surface it doesn't edit.
  2. One thing, one home. Every setting has exactly one editor. Another page may show it read-only with a link ("Button: Wind, left side · Edit on Controller"), never a second form.
  3. The list belongs to the page. Data lists files, Map lists At rest and layers, Controller lists buttons by side. At rest stops being a tab: it is the top of Map's list, because it edits the same surface as the layers.

Pages: Place · Data · Map · Controller · Phones · Present. Display (calibration, colour, quality) belongs to this computer and moves to the app's settings, opened from Present. The setup guide walks the same pages in order.

Journey map: a returning author

  • Opens a table from Home: the editor starts on Edit with At rest selected. That is fine, but the tab order doesn't hint at what's left to do (no ✓ for finished setup, no "3 warnings before presenting").
  • Wants to add one GeoJSON: finds Add data (asks what the file holds first) or Media › Add media (takes the file first). Two doors that behave differently.
  • Tweaks a layer's look, then opens Display to check colour: the right panel still shows the Wind layer's settings. Opens Design: Wind gets selected and shown on the map without being asked.
  • Checks it on the real displays with Present, edits, and presents again. A rehearsal on this screen is missing (#97).

Friction, ranked by how much it hurts the flow

1

The ribbon and the guide are two different maps of one journey #382

Guide: Name and place · Your place · At rest · Layers · Buttons · Ready. Ribbon: Edit · Name and place · At rest · Design · Display · Media · Help. Edit (step 4) comes first, Your place and Ready have no tab, Buttons became Design, and the guide hides the ribbon entirely, so the guide teaches nothing about where things live afterwards.

Proposal. One spine in journey order, shared by both: Place · Data · At rest · Layers · Controller · Present, then Display set apart as this computer's settings. Help becomes a ? button, Share sits next to Present. The guide becomes a coach card over the same workspace: tabs tick off as you go, Next moves to the next tab, and Close guide leaves you where you are.
2

The Edit ribbon runs off the screen #383

All 17 layers are large buttons, so at 1440 px wide, Make your own, Selected, Add data and Open in a window are off the right edge, behind a sideways scroll with no scrollbar. Each new core layer makes it worse, and Help has the same problem.

Proposal. Add a layer becomes one dropdown that opens the #59 gallery (search, categories, what each layer needs). The Selected group stays fixed. Groups shrink to icons when space is short, so nothing is ever hidden.
3

Switching tabs changes what you are looking at #385

Design selects Wind and shows it on the map. Display and Help keep Wind's inspector on the right. Picking a layer in the list throws you back to Edit from any other tab. A tab should change the tools, not the selection or the map.

4

The same setting lives in two or three places #384

Map life switches are in the Edit ribbon, the At rest ribbon and the At rest panel (the last two side by side). Add data is in three ribbons. Move the table is in the ribbon and the panel footer. A button's words are in Design and in the inspector. Preview, Open in a window and Window all open the same views.

Proposal. A rule for the editor: the ribbon holds actions and the panel holds settings, with one home for each. Preview becomes Rehearse (#97).
5

Two doors for files #52

Add data asks "The file holds…" before you pick a file. Add media takes the file and works out what it is. One file-first way in, in the Data tab, with drop-anywhere, is simpler. I added this to #52 instead of opening a new issue.
